# V5.5：实现 DOCX → Markdown + Annotation 导入

当前 V1～V5 已完成。

现有系统至少包括：

* 私有白名单 Sign in with ChatGPT
* Markdown-first WYSIWYG Post
* Post Revision / asset snapshot
* Soft Delete / Admin Hide / Restore
* Activity / Notification
* Annotation Markdown AST extension
* ProseMirror Annotation Mark
* Annotation Replies
* Annotation revision snapshot / restore

本次只实现：

> **将 `.docx` 文件导入为本站 canonical Markdown + Annotation + Annotation Replies。**

目标不是 Word renderer，而是：

> **将 Word 中本站能够表达的语义内容确定性地转换为现有数据模型；不能表达的内容按照明确规则降级或拒绝，不允许静默损坏数据。**

---

# 1. 本次支持范围

支持：

* 标题
* 段落
* H1～H4
* 粗体
* 斜体
* 删除线
* 有序 / 无序列表
* 最多 3 层嵌套列表
* Quote / Intense Quote
* 链接
* 基础矩形表格
* PNG / JPEG / GIF / WebP 图片
* 普通 Word comment
* comment author / initials / date
* 能可靠解析的 threaded replies
* Word resolved comment metadata

---

# 2. 明确不实现

不实现：

* Word 像素级排版
* 字体 / 字号 / 颜色
* 页边距
* 页眉页脚
* 分页
* 页码
* TOC 页码
* 浮动对象精确布局
* Shapes / SmartArt
* Track Changes 历史
* 复杂域代码语义
* cross-block Annotation
* overlapping Annotation
* nested Annotation
* 图片 Annotation
* DOCX export
* PDF / ODT import

Track Changes 若存在，只导入**接受所有修订后的最终文本状态**，不保留修订历史。

---

# 3. 导入权限

所有当前有效白名单用户都可以导入 DOCX。

导入后：

```text
post.author_id = importer_user_id
```

DOCX 中的 Word author 不影响 Post author。

管理员不拥有特殊的 Import-only 路径。

---

# 4. 解析位置

DOCX 默认在：

> **浏览器 Web Worker**

中解析。

原始 `.docx` 默认：

* 不上传服务器
* 不存 D1
* 不存 R2
* 不做长期保留

原因：

* 避免占用 Sites server CPU
* 原始私人 Word 文档无需离开浏览器
* 解析失败不会污染后端

Web Worker 必须支持：

* progress
* cancel
* timeout
* structured error

---

# 5. 服务端信任边界

浏览器解析出的 Import IR **不可信**。

最终 commit 前，服务端必须验证：

* 当前 authenticated user
* allowlist
* IR schema
* Markdown size
* asset ownership
* Annotation invariant
* annotation IDs
* attributed user IDs
* 数量上限
* import batch id
* duplicate commit

服务端不需要重新解析原始 DOCX。

DOCX import 是用户内容输入方式，不是数字签名或真实性认证系统。

---

# 6. officeparser 判定门

当前 `officeparser` 7.x 已有：

* structured AST
* Markdown generator
* browser build
* comments metadata

但不要默认将它作为生产导入路径。

开发开始时允许进行一个：

> **最长 2 小时的 feature probe**

使用实际安装的版本和本 spec fixtures。

必须同时证明：

1. comment anchor 能精确到 inline range，而不是仅 paragraph/node
2. adjacent comments 不会合并
3. nested/overlapping comments 能区分
4. comment ID 稳定可获取
5. threaded reply parent 可获取
6. resolve state 可获取
7. 不需要 selectedText 反向搜索

全部通过才能考虑使用。

任何一项失败：

> **停止 officeparser production-path 评估，使用下文 OOXML Import Walker。**

无论结果如何，将版本和结论记录在代码注释或 ADR 中。

# 7. 第三方库原则

默认生产方案：

> 自己实现针对本 scope 的轻量 OOXML Import Walker。

第三方库可以用于：

* ZIP
* XML parsing
* 测试交叉验证
* fixture inspection

不要依赖 Mammoth 提供 comment range。

如果使用 Mammoth，只允许把它作为正文转换结果的参考 / regression oracle。

不要使用 Mammoth deprecated Markdown output 作为 canonical importer。

不要默认引入 Docxodus/WASM。

---

# 8. DOCX package 基础校验

文件必须：

* extension 为 `.docx`
* ZIP signature 合法
* 存在 `[Content_Types].xml`
* 存在 `word/document.xml`

如果文件以 OLE Compound File magic：

```text
D0 CF 11 E0 A1 B1 1A E1
```

开头：

明确拒绝：

> 不支持旧版 `.doc` 或加密 / 受保护的 Office 文档。

不要尝试破解密码。

---

# 9. 输入限制

固定第一版限制：

```text
压缩 DOCX ≤ 20 MB
ZIP entries ≤ 1000
总解压数据 ≤ 200 MB
任一 entry 压缩比 ≤ 100:1
单 XML part ≤ 20 MB
XML nesting depth ≤ 100
图片 ≤ 200 张
单图片 ≤ 10 MB
root comments + replies 合计 ≤ 500
最终 canonical Markdown UTF-8 ≤ 1.5 MB
Web Worker parse timeout = 20 秒
```

超过限制：

停止解析并返回 typed error。

不要“尽量继续”。

---

# 10. XML 安全

所有 XML parser 必须：

* 禁止 DTD
* 禁止 external entity
* 不获取任何远程 XML resource

发现：

```text
<!DOCTYPE
<!ENTITY
```

直接拒绝。

不要解析 XML 中声明的任意外部实体。

---

# 11. OOXML parts

根据实际存在情况读取：

```text
word/document.xml
word/styles.xml
word/numbering.xml
word/_rels/document.xml.rels

word/comments.xml
word/commentsExtended.xml

word/footnotes.xml
word/endnotes.xml

docProps/core.xml

word/media/*
```

缺少可选 part 不应失败。

缺少主 document part 必须失败。

---

# 12. Import IR

不要：

```text
DOCX → HTML → Markdown → 再猜 comment range
```

先产生本站专用：

```text
DocxImportIR
```

核心结构概念上：

```text
Document
  blocks[]

Block
  type
  sourceOrder
  children[]

InlineSegment
  text
  marks
  link?
  commentIds: Set<WordCommentId>
```

Annotation range 是 IR 本身的属性。

不存在后续“把 OOXML offset 映射到 Markdown offset”的步骤。

---

# 13. document.xml 单遍正文遍历

预先读取：

* styles lookup
* numbering lookup
* relationship lookup
* comments lookup
* commentsExtended lookup

随后按照 `document.xml` 正文顺序遍历一次。

遇到：

```text
commentRangeStart(id)
```

将 id 加入当前 active comment set。

遇到文本 run：

该 InlineSegment 自动继承当前 active comment IDs。

遇到：

```text
commentRangeEnd(id)
```

结束该 id。

因此 Comment range 与正文在**同一次解析过程中形成**。

严禁使用：

```text
正文生成完成
→ 搜索 selectedText
→ 推测 comment range
```

---

# 14. Offset 的唯一用途

允许从完成后的 IR 计算：

```text
blockLocalStart
blockLocalEnd
```

仅用于：

* overlap 检测
* deterministic sort
* preview/debug

这些 offset 使用 JavaScript UTF-16 code-unit semantics。

它们不是 DOCX → Markdown source mapping。

不要在生成 IR 之前做 Unicode normalization。

---

# 15. Heading 识别

读取 paragraph 的：

```text
w:pStyle
styles.xml
w:basedOn
w:outlineLvl
```

规则：

1. 优先解析有效 paragraph style
2. 沿 `basedOn` 链解析
3. style id / name 规范化后若明确为 Heading1～Heading9，使用对应 level
4. 否则使用 effective `outlineLvl` 作为兜底

本站只支持 H1～H4。

H5～H9：

```text
→ H4
→ warning HEADING_LEVEL_CLAMPED
```

不要根据：

* 字号
* 粗体
* 居中

猜标题。

---

# 16. Quote 识别

仅将明确 style：

```text
Quote
IntenseQuote
```

或规范化后等价 style id/name 识别为 blockquote。

不要根据：

* 左缩进
* 字体
* 灰色背景

猜 blockquote。

无法识别则普通 paragraph。

---

# 17. 列表解析

通过：

```text
paragraph numPr
→ numId
→ numbering.xml w:num
→ abstractNum
→ ilvl
→ numFmt
```

判断：

* ordered
* unordered
* nesting level

`numFmt=bullet`：

→ unordered list。

其他常见 numeric / alphabetic / roman：

→ ordered list。

最大导入 3 层。

Word 第 4 层及以后：

```text
→ flatten 到第 3 层
→ INFO LIST_DEPTH_CLAMPED
```

同类 warning 聚合计数。

---

# 18. Inline formatting

支持：

```text
w:b       → strong
w:i       → em
w:strike  → strike
```

处理 style inheritance 后得到 effective formatting。

不导入：

* underline
* color
* font
* font size
* highlighting

这些属于被明确忽略的视觉格式。

不要逐 run 产生 warning。

只允许聚合成一个可选 INFO：

```text
VISUAL_FORMATTING_DROPPED
```

---

# 19. Inline code

Word 没有通用 code 语义。

只允许通过明确 character style 白名单识别：

```text
Code
CodeChar
SourceCode
```

具体默认白名单在代码中集中配置。

不要因为“字体是 Consolas / Courier New”就自动认为是代码。

未命中 whitelist：

按普通文本导入。

---

# 20. Hyperlinks 与 Fields

普通：

```text
w:hyperlink
```

通过 relationship 获取 URL。

只允许安全 scheme：

```text
https:
http:
mailto:
```

拒绝：

* file:
* javascript:
* data:
* UNC
* 任意未知 scheme

Word Field：

* 不保留 field instruction
* 默认保留当前 cached/display result text

例外：

```text
TOC field
```

整段 TOC field 跳过：

```text
INFO TOC_SKIPPED
```

因为本站不保留分页和目录页码。

---

# 21. Track Changes

V5.5 不导入 revision history。

统一转换成“接受全部修订后的最终状态”：

```text
w:ins / moveTo → 保留内容
w:del / moveFrom → 不导入
```

如果文件存在 revision markup：

增加一个聚合：

```text
INFO TRACK_CHANGES_FLATTENED
```

不要逐项产生 warning。

---

# 22. 基础表格

只支持能够转换成矩形 Markdown table 的普通表格。

若第一行明确带 Word header semantics：

→ 使用第一行作为 Markdown header。

否则：

→ 合成空 header row
→ 所有 Word rows 保持为 data row
→ INFO TABLE_HEADER_SYNTHESIZED

Cell 内允许：

* text
* strong/em/strike
* link

Cell 内多个 paragraph：

```text
使用 " / " 连接
→ WARNING TABLE_CELL_FLATTENED
```

Markdown table cell 内不导入 Annotation。

如果 Word comment anchor 位于 table：

整个对应 comment thread 跳过。

---

# 23. 合并单元格

如果检测到：

* rowSpan
* colSpan
* vMerge
* gridSpan

不强行生成错误 Markdown table。

将整张表转换为按行排列的可读纯文本：

```text
cell A | cell B | cell C
```

并：

```text
WARNING TABLE_MERGED_CELLS_FLATTENED
```

不要使用 raw HTML table。

---

# 24. 图片

支持：

```text
PNG
JPEG
GIF
WebP
```

根据 relationships 读取 embedded media。

图片 alt：

优先：

```text
wp:docPr@descr
```

其次：

```text
wp:docPr@title
```

其次：

文件名。

都没有则：

```text
image
```

Preview 时上传到现有 temporary R2 asset pipeline。

Canonical Markdown 使用现有图片 node / URL。

---

# 25. 不支持图片格式与浮动图

第一版不直接导入：

* EMF
* WMF
* SVG

产生：

```text
WARNING IMAGE_FORMAT_UNSUPPORTED
```

不要把潜在 SVG 直接放到同源 R2 后公开。

Word floating image：

如果底层图片格式受支持：

* 忽略精确 wrap/x/y
* 放到最近合理正文位置
* INFO FLOATING_IMAGE_FLATTENED

# 26. 其他特殊内容

`w:txbxContent`：

如果能提取文本：

→ 在锚点附近降级成普通 paragraph
→ WARNING TEXTBOX_FLATTENED

OMML Equation：

→ 输出字面占位 `[公式]`
→ WARNING EQUATION_SKIPPED

SmartArt / Shape 无可读文本：

→ 跳过并 warning。

如果存在可读文本：

优先保留文本。

# 27. Footnotes / Endnotes

不实现本站 Footnote AST。

但不要静默丢掉 note 内容。

正文 reference 降级为：

```text
[1]
[2]
```

文末增加：

```text
---

脚注（从 Word 导入）

[1] ...
[2] ...
```

Endnotes 同样进入该 appendix。

产生一次：

```text
INFO NOTES_FLATTENED_TO_APPENDIX
```

Note 中的 Word comments 不导入 Annotation。

---

# 28. Word Comment Definition

从：

```text
word/comments.xml
```

读取：

* Word comment id
* author
* initials
* date
* comment body
* comment source order
* 最后 paragraph 的 `w14:paraId`（若存在）

root comment 必须拥有可解析的正文 text range。

---

# 29. Word Threaded Replies

如果存在：

```text
word/commentsExtended.xml
```

解析：

```text
w15:paraId
w15:paraIdParent
w15:done
```

通过 comment 最后 paragraph 的 `w14:paraId` 建立：

```text
comment
→ CommentEx
→ immediate parent comment
```

没有 `paraIdParent`：

→ root。

有：

→ reply。

如果文件没有 commentsExtended：

所有 comments 视为 flat root comments。

不要猜 reply relationship。

---

# 30. Resolved Comments

Word：

```text
w15:done = 1
```

不映射成本站新的 resolve 功能。

Imported Annotation 记录：

```text
source_resolved = true
```

UI 可显示：

> Word 中已解决

但在本站仍按普通 imported thread 显示。

不要因此自动隐藏。

---

# 31. Thread 是原子导入单元

一个 Word root comment + 它的全部 replies：

> 视为一个 thread。

如果 root 无法导入：

整个 thread 跳过。

Replies：

* 不提升为 root
* 不变成孤儿
* 不创建无 anchor Annotation

Warning 只生成一条，并包含：

```text
replyCount
```

---

# 32. Annotation 合法性

Word root comment 只有同时满足以下规则才能进入本站：

* 非空 text range
* range 完全位于单个普通 text block
* 不在 table
* 不在 image
* 不在 footnote/endnote
* 不跨 block
* 不与已接受 Annotation 重叠
* 不嵌套
* 不引用不存在 comment definition

空 range / point comment：

```text
→ 整 thread 跳过
→ WARNING ANNOTATION_EMPTY_RANGE
```

---

# 33. Overlap 决策规则

对同一 block 的 root comment ranges 按：

```text
startOffset ASC
length DESC
sourceCommentId ASC
```

排序。

然后 greedy accept。

若候选 range 与已接受 range：

```text
intersects
```

则跳过该 thread。

Warning：

```text
ANNOTATION_OVERLAP_SKIPPED
conflictsWithSourceCommentId
```

端点仅相接：

```text
A.end == B.start
```

不算 overlap。

因此 adjacent Annotation 合法。

---

# 34. Imported author 身份模型

Imported Annotation 绝不能伪装成站内原生发言。

Imported root/reply：

```text
author_id = NULL
source_type = DOCX_IMPORT
source_author_name
source_initials
source_created_at
source_comment_id
import_batch_id
imported_by_user_id
attributed_user_id = nullable
```

`author_id` 对 imported content 永远保持 NULL。

---

# 35. Author Mapping

Preview 可以让 importer 显式关联：

```text
Word "林柚子"
→ 本站 user_id XYZ
```

这只写：

```text
attributed_user_id
```

不能写：

```text
author_id
```

UI 必须始终显示来源，例如：

> 林柚子 · Word 导入 · 关联 林柚子

不能让 imported comment 与原生站内 Annotation 无法区分。

---

# 36. Attribution 权限与透明通知

`attributed_user_id`：

不获得：

* 编辑权
* 删除权
* 内容所有权

因为该用户没有在本站真正发布这段文字。

Import 完成后：

如果某个本站用户被关联到一个或多个 Word comments：

只发送**一条汇总通知 / import batch**：

> X 导入《帖子》，其中 3 条 Word 批注与你关联。

不要每条 comment 发通知。

不要创建对应个人 Activity。

---

# 37. Imported Annotation 删除权限

Imported Annotation / Reply 都是 immutable。

不能“编辑”。

普通 attributed user 不能删除。

Post 作者 / importer 可以：

> Remove imported annotation thread

该操作遵守现有 soft-delete：

* 如果没有后来产生的 native replies，可完整退出当前视图
* 如果已有 native site replies，保留 anchor + deleted imported placeholder
* native replies 绝不能被连带删除

管理员继续拥有 V5 hide / restore 权限。

---

# 38. 时间与排序

Imported Annotation：

```text
created_at = commit 时间
source_created_at = Word comment 时间
source_document_order = Word comment 顺序
```

批注 sidebar 顺序首先按：

```text
anchor position
```

同一 thread 内 replies：

```text
source_created_at ASC
→ 缺失时 source_document_order ASC
→ source_comment_id ASC
```

保证稳定。

---

# 39. UUID 与 Import Batch

进入 Preview 前生成：

```text
import_batch_id = UUID
```

构建 IR 时就为每个被接受的 root/reply 铸造最终本站 UUID。

Preview 与 Commit 必须使用同一组 UUID。

不要 commit 时重新生成。

`import_batch_id` 是服务端幂等键。

同一个 batch 重复 commit：

必须返回同一个结果或明确 already committed。

绝不能创建两个帖子。

# 40. Preview State

> IndexedDB

包含：

* import_batch_id
* source filename
* source SHA-256
* parsed IR
* warnings
* temporary asset refs
* author mappings
* generated annotation IDs

TTL：

```text
24 小时
```

原始 DOCX binary 不需要写入 IndexedDB。

刷新页面后可以恢复尚未提交的 Import Preview。

# 41. Warning Model

所有 warning 使用机器可读结构：

```text
{
  code,
  severity: "info" | "warning" | "error",
  sourceRef?,
  count?,
  payload?
}
```

不要只保存自然语言字符串。

UI 再负责本地化说明。

同类 cosmetic warning：

* 聚合
* 显示 count
* 不逐 run 展开

Annotation 被跳过：

必须逐 thread 保留具体 source reference。

Preview 最多默认展开 50 条 warning，其余按类别聚合。

# 44. Post Title

建议标题：

1. `docProps/core.xml` 中非空 title
2. 否则文件名去掉 `.docx`

正文中的第一个 H1：

不自动删除。

因此可能出现：

```text
Post title = 文档标题
正文第一行 = # 文档标题
```

这是允许的。

用户可在 Preview 中自行修改 Post title 或正文。

不要擅自猜重复内容并删除。

---

# 45. Commit 与一致性

确认导入后：

DB 侧使用**单次 D1 `batch()`**完成正式关系数据写入。

包括：

* post
* initial revision
* asset refs
* annotations
* annotation replies
* annotation snapshot
* import batch metadata
* POST_CREATED activity
* attribution summary notifications

为避免 bound parameter 上限：

使用有限大小的 bulk insert chunks，再放入同一个 batch。

如果 batch 任一 statement 失败：

整个 DB batch 必须 rollback。

---

# 46. R2 与 D1 一致性

Preview 图片已经作为：

```text
temporary assets
```

存在 R2。

Commit 不需要移动 R2 object。

D1 batch 成功时：

在 DB 中将相关 asset refs 绑定到 post/revision。

如果 DB commit 失败：

R2 对象继续保持 temporary。

由现有 7-day GC 回收。

因此：

> 不要求 R2 与 D1 实现不存在的跨存储原子事务。

---

# 47. Initial Revision

一次 DOCX import：

只创建一个完整 initial revision：

```text
title
markdown
assets
imported annotation state
imported replies
```

不要：

```text
先创建无批注 v1
→ 每条 Word comment 再产生 annotation-state revision
```

导入后的初始状态就是一个整体 snapshot。

---

# 48. Activity / Notification

Import：

创建正常：

```text
POST_CREATED
```

Activity。

不要为历史 Word comments 创建：

```text
ANNOTATION_CREATED
ANNOTATION_REPLY_CREATED
```

Activity。

不要为它们产生正常实时互动通知。

唯一例外：

> `DOCX_ATTRIBUTION_NOTICE`

每个 attributed user 每个 batch 最多一条汇总通知。

# 49. 服务端 Import IR 校验

Commit 前重新检查：

* import_batch_id 未提交
* post title / markdown size
* annotation UUID 唯一
* 每个 annotation 属于当前 post IR
* root range 不重叠
* annotation/reply 数量上限
* author_id 对 imported content 必须 NULL
* attributed_user_id 必须是合法站内 user
* temporary asset 属于 importer
* 所有 asset type 合法
* external URL scheme 合法

客户端无法通过手写 IR：

* 冒充原生用户 Annotation
* 插入其他 post annotation ID
* 引用别人的 temporary assets
