# 浩劫双人确认悔棋

来源：2026-09-22 用户要求沿用游戏按钮，一方申请、另一方弹窗同意后回退上一步。

- 一步为游戏原有的一次成功命令；双方均可申请撤销最新一步，每次回退均需另一方同意。只处理进行中的对局，不撤销认输/终局，不提供在线重做。
- 申请期间暂停游戏命令；申请方可撤回，对方可同意或拒绝。对方关闭确认框等同拒绝。认输仍可结束对局并清除申请。
- `RoomClient` 复用原轮询、单在途写入、UUID 重试与回执；请求、拒绝、撤回、同意均推进房间修订号，回退不降低修订号。客户端只接受服务器按席位脱敏的快照。
- `haojie_history` 按房间/命令修订保存操作前完整状态，最多最近60步，与本地历史上限一致；轮询只查询是否存在历史，同意时读取最近两项以恢复一步并更新可撤销标识。随机数、反应、阶段、日志等随状态整体恢复，重做相同召唤不会刷新随机结果。
- 历史保存/裁剪、申请状态、回执与局面写入在既有 D1 CAS 事务内完成。第三人、申请方自行同意、旧申请编号、过期修订、待确认期间落子均由服务端拦截。神龛独立选择仅能跨过另一条紧邻游戏命令重定基，不能跨悔棋确认过程。
- 数据库迁移只增加表与 nullable 字段。既有房间此前没有历史，发布后的下一次成功命令开始可悔棋；不改动现有局面或引擎版本。
- 界面复用 `Battlefield` 的悔棋按钮、网站 `ModalDialog`、现有同步反馈和按钮样式；在线组件只新增宿主回调，维护位置见 `vendor/haojie2/SOURCE.md`。适用 D1–D8、U1/U2/U4/U9/U10；同类弹窗为房间认输确认。

验证：既有 `tests/haojie/rooms.test.ts` 覆盖真实 D1 的同意/拒绝/撤回、重试、竞态、事务失败、隐私、确定性与连续回退；传输测试覆盖申请同步。构建产物 HTTP 测试覆盖 `/undo` 路由与成员权限。工程检查与真实双账号浏览器验收分别记录，不将模拟环境当作端到端浏览器验收。

实施验收：上述联机/传输测试21项通过；生产 Worker HTTP 测试1项通过（含迁移、游戏组权限、申请、对方同意、回执重试与恢复完整局面）；TypeScript、ESLint、生产构建、改动文件格式检查与 strict premium UI audit 通过。真实双账号浏览器交互尚未验收。上游规则对话框在宿主暂停操作时关闭，避免原生 top-layer 覆盖悔棋确认。
