## 1. 目标与已确认方向

保留暖白纸色、校园绿、校刊式长文阅读感；重构空间组织、信息密度和组件行为，使页面更现代、精致、流畅。以后增加功能时，应能依据既有结构找到合适位置，而不是不断新增页面宽度、断点和局部覆盖样式。

用户已认可首页、带批注详情页和 DOCX 导入预览样板。视觉基准概括为：

- 首页使用紧凑文字列表和明确分页，内容直接进入首屏。
- 文章纸面是视觉核心，正文与辅助讨论分工明确。
- 导入预览以正文为主，检查、作者关联、导入批注进入右栏。
- 功能页采用紧凑标题和就近帮助；减少重复说明、层层卡片、过重阴影。
- 品牌与正文可使用衬线字体；导航、控件、列表和管理界面使用清晰的无衬线字体。
- 页面宽度由任务决定，外侧边距、操作层级、密度档位和响应式转换规则保持一致。

**样板批准不等于样板代码可以直接用于生产。** 样板数据、每页 6 条、模拟按钮、示例作者、示例讨论数、简化的批注浮层和工具栏均为演示。正式实现必须接入真实查询、现有编辑器和权限模型；不复制演示中的 HTML 拼接、模拟成功提示或简化线程。

### 1.1 本次包含

全站布局和视觉规范；公共导航；浏览列表；真实分页和计数；搜索一致性；文章、编辑器和导入工作区；管理后台视觉迁移；通知、个人页、设置、标签页和状态页；组件复用；响应式、可访问性和交互稳定性。

### 1.2 边界

本轮不增加点赞、收藏、关注、推荐、封面系统、全局左侧导航、深色模式、密度切换器或列表/Grid 切换器。也不更换框架、Markdown 编辑器、数据库或整套组件库。已有能力继续保留，尤其是权限、批注保护、草稿恢复、历史版本、冲突处理和内容生命周期。

“留出空间”通过稳定的页面结构和明确的组件职责实现，不提前开发没有业务用途的功能槽位或配置平台。

## 3. 页面结构与空间体系

### 3.1 三种页面结构

| 结构 | 使用页面 | 页面组成 | 滚动归属 |
| --- | --- | --- | --- |
| 浏览页 | 首页、搜索、标签详情、个人帖子/动态、通知 | 单列：紧凑标题 → 筛选/操作 → 结果 → 分页；不设常驻辅助栏 | 文档滚动 |
| 阅读/写作工作区 | 帖子、编辑、导入预览、历史预览 | 上下文导航/操作 → 正文纸面 → 辅助面板 | 正文随文档滚动；浮层内部滚动 |
| 管理工作区 | 管理总览、内容、成员、日志 | 管理导航 → 主面板 → 可选辅助面板 | 保留当前后台视口工作区；各面板单独规定滚动 |

不向所有页面新增侧栏。文章批注、导入检查、管理摘要拥有各自业务职责，共享布局基础，不合成一个万能侧栏组件。

### 3.2 尺寸起点

以下数值用于首轮实现，须通过真实内容验证。宽度表示容器边框盒最大宽度；外侧页面 gutter 不计入。按此口径记录规范，避免同一个数字在不同页面代表不同层级。

| Token / 用途 | 起点 | 说明 |
| --- | --- | --- |
| 浏览页外框及 Header 内框 | 1040px | 首页、搜索、标签、个人页、通知、设置及初始导入 |
| 阅读/编辑/导入预览外框及 Header 内框 | 1320px | 为文章纸面与真实业务面板提供宽度 |
| 普通帖子列表 | 填满1040px浏览外框 | 标题、工具栏、帖子行、分页共享左右基线 |
| 通知消息区 | 880px | 是1040px页面壳中的居中内列，不是另一个页面壳 |
| 设置/初始导入表单 | 720px | 是1040px页面壳中的居中内列 |
| 正文净宽 | 720px | 阅读、新建、编辑和导入尽量一致 |
| 文章纸面横向内边距 | 32px | 窄屏减至 20px；正文上限独立保留 |
| 文章纸面总宽 | 786px | 720 + 32×2 + 1px 边框×2 |
| 批注沟槽 | 56px | 为连线与正文/卡片分离保留空间 |
| 批注侧栏 | 340–400px | 充分利用宽屏，保持紧凑线程 |
| 导入检查侧栏 | 320px | 正文纸面与检查栏间距 24px |
| 管理工作区及 Header 内框 | 1800px | 共用外侧边缘；导航初始沿用208px |
| 外侧 gutter | 桌面 24px；手机 16px | 所有社区页统一 |
| Header | 桌面 64px；手机 60px | 长内容和文本缩放时允许增高，不截断 |
| 标题区上方间距 | 桌面 24–28px；手机 20px | 替换普通页 46px 的统一大留白 |

**对齐关系：** Header背景可以通栏，Logo与账户区所在的内框按上述页面类型选宽；PageHeader、工具栏、正文工作区的外框与它共享左右边缘及gutter。首页不再是1320px Header套1040px内容。后台不再沿用较窄的社区Header。通知消息区、设置表单和文章纸面属于显式内列，它们可有内缩；不要求Logo直接贴齐每一段正文文字。

首页不预留“右侧280px”槽位：页面外框本身就是1040px。留在页面外框外的两侧空白用于聚焦内容，不代表缺失的侧栏。首页“标签”入口位于排序工具栏右端，并保留头像菜单中的“全部标签”；不新增“关于本站”、相关标签、筛选摘要或统计卡填空。

普通文章和有批注文章始终选择同一个1320px阅读外框。在能显示双栏的宽度下，两者都使用同一个最大1242px组合网格，纸面固定在第一列；无批注时右侧业务栏为空且不可聚焦，纸面不重新居中。只有容器进入紧凑模式，纸面才随整个模式转换居中；变化只由可用宽度决定，与批注数量无关。回复区跟随同一纸面列。列表中的摘要另按浏览密度排版。

### 3.3 断点按实际空间计算

批注目前以实际容器宽度 1116px 判定桌面模式，依据是 720 + 56 + 340。这一规则基于旧 DOM 包裹关系。

新的独立纸面与右栏组合采用上述尺寸时，至少需要 **1182px = 786 + 56 + 340**。令C为扣除外侧gutter后的工作区可用宽度，W=min(C,1242px)。W≥1182px时显示双栏，纸面786px、沟槽56px、侧栏R=min(400px,W−842px)；W<1182px时进入紧凑模式。W=1182时R=340，W=1242时R=400；C更大时组合网格居中，不能继续拉宽侧栏。该公式同时用于有/无批注文章的纸面定位。审查者给出的1182–1319直接相减会使部分侧栏超过400，因此本版采用明确上限。

实施时必须确定测量对象确实是上述工作区，而非正文DOM或含额外padding的祖先。禁止直接把旧阈值替换成视口断点。

- 桌面/紧凑模式仍由一个共享 owner 计算，CSS、连线、侧栏、编辑器和 Sheet 消费同一模式结果。
- 小于完整组合所需宽度时，保留正文行宽与操作入口，批注进入现有 bottom-sheet。
- 导入预览双栏至少需要 1130px = 786 + 24 + 320；不足时检查区重排，必要提醒与确认动作仍可见。
- Header 的搜索和账户操作按实际可用宽度降级。窄屏搜索可展开；头像、通知和写帖入口保留，不能仅通过隐藏内容解决溢出。
- 改变窗口大小不应重置输入、选择或当前线程。桌面与 Sheet 切换保持选中的 annotation ID，防止双份线程输入同时挂载。
- 页面外框类型由稳定的路由布局决定，Header与内容同次渲染；不在客户端挂载后再突然改宽。DOCX同一路由的初始/解析→预览扩展是明确的工作阶段转换，Header和工作区一起切换；恢复已有预览时直接采用预览框架，避免先窄后宽闪烁。

## 4. 视觉语言

### 4.1 颜色与字体

以已认可样板为起点：纸色 `#FBFAF7`、内容纸面 `#FFFEFA`、墨色 `#242D27`、辅助文字 `#626B62`、主绿 `#386647`、浅绿 `#EDF3EB`。错误、警告、批注等语义颜色沿用现有用途，对比度验证后微调。颜色变化同步到规范和 `app/globals.css :root`。

| 角色 | 起点 | 使用约束 |
| --- | --- | --- |
| 功能页标题 | 26px / 1.35 | 手机约 24px；允许长标题换行 |
| 文章标题 | 32px / 1.45 | 衬线；手机约 27px |
| 列表标题 | 18px / 1.5 | 无衬线，最多两行，完整标题保留可访问名称 |
| 长文正文 | 18px / 1.9 | 中文衬线栈，实际检查长段落、英文及标点 |
| 常规控件、帮助 | 14px / 1.5–1.7 | 帮助靠近对应动作 |
| 时间、来源等元数据 | 12–13px | 不承载唯一的关键操作说明 |
| 桌面批注正文 | 13px / 1.7 | 与认可样板一致；不把13px作为所有普通正文默认 |
| 紧凑模式批注Sheet正文 | 14px / 1.7 | 与认可样板浮层一致；使用共享紧凑模式变体 |

**字体明确选择：本轮使用本地中文衬线回退，不增加标题子集或整套正文自托管字体。** 标题及文章优先使用本地`Noto Serif SC`，再用`Songti SC`、`STSong`、`SimSun`、`serif`；控件和线程使用无衬线栈，Windows优先`Microsoft YaHei`。Windows缺少前几项字体时明确接受宋体/系统serif作为阅读回退，不承诺与macOS逐像素相同。这延续样板的`Noto Serif SC/Songti SC/SimSun/serif`选择；“未加载Web字体”不等于“正文一定变成无衬线”。

校刊感由纸面、行宽、标题与留白共同建立，不只押在一个字体上。实施时必须展示Windows实际回退结果；若发现可读性问题，应按真实证据集中调整字重/行距或该语义字号，不能靠CSS层层覆盖、浏览器UA猜测或静默引入字体文件补救。未经重新评估，不把任意用户标题子集化成固定几十KB并宣称能覆盖将来的中文正文。13px的可读性要连同字体、对比度、行高和缩放检查，不采纳“所有中文13px必然不可读”的一概判断。

### 4.2 形状、间距与动效

- 建立少量语义 token：页面间距、区块间距、控件 gap、纸面 padding、常规/紧凑控件尺寸。不要把每个 CSS 数字都提升为全局 token。
- 控件圆角约 7–8px，纸面及独立面板约 10px，弹窗约 12px；胶囊仅用于合适的计数和状态。
- 普通列表用细分隔线与轻背景反馈；阅读纸面允许极轻阴影；浮层阴影表达层级。
- 常规控件高 40px，紧凑工具栏 36px；粗指针有效点击目标以 44px 为目标。元数据并非都要变成 44px 高按钮。
- 悬停以色彩和边线变化为主，取消普通帖子行与按钮普遍上浮。保留清楚的 focus-visible、按下、disabled、busy 状态。
- 常规反馈约 150ms；减少动态偏好时取消非必要运动。批注仅点击、键盘和深链触发定位，悬停不滚动。

### 4.3 语义色与批注连线

| 语义 | 文字/强调色 | 浅表面 | 用法 |
| --- | --- | --- | --- |
| 品牌/选中 | `#386647` | `#EDF3EB` | 安全主操作、当前选择；主按钮绿底配暖白字 |
| 成功 | `#386647` | `#EDF3EB` | 完成图标＋结果文字，可复用品牌色但必须有语义标签 |
| 危险 | `#9B3933` | `#FBECEA` | 删除等后果；强填充只用于确认中的最终危险动作 |
| 警告 | `#75591F` | `#F7F0E2` | 格式损失、待确认影响、可恢复风险 |
| 信息 | `#536257` | `#F0F3EF` | 中性帮助、提示、普通状态 |
| 批注 | `#833F3A` | `#F8E9E5`；激活底`#F0D2C9` | 正文标记、线程定位；专用token，不复用danger |
| 已删除/隐藏占位 | `#626B62` | `#F2F3EE` | 正常字重的状态句＋可选图标；不是新的警告或危险按钮 |

保留样板的暖玫瑰批注色，不因它与危险色都偏暖就改掉身份。颜色token、浅表面和使用情境必须不同；危险通过动作文案与确认表达，批注通过范围底色、点状下划线和线程关系表达。上述色对都在实际表面上验证对比度。

**连线默认策略：** 未选择线程时不绘制整屏connector；保留卡片按锚点排序、对齐和碰撞避让。点击、键盘激活或通知深链选中一条线程后，仅绘制这一条的细实线，并加深该范围与卡片的选中态；切换线程时替换连线，退出选择时移除。单纯hover不创建连线、不滚动、不改变选中ID；线程内部获得键盘焦点时显示该线程连线但不强制滚动。Sheet模式不画线。

任意时刻最多一条连线：线程内部的键盘焦点优先于已有选中ID；焦点离开线程后恢复仍有效的选中ID。折叠、删除或切换后目标不可见时不留下孤立线。这个优先级由共享选中状态处理，不能分别在卡片和正文各维护一条线。

这是对样板安静默认态的生产补充，不是从“样板未实现连线”推导出删除connector能力。长距离连线仍按现有锚点和布局结果计算，不画所有粉色虚线，不新增跨线程线束。

### 5.1 首页与帖子行

采用轻列表，不设 150px 最小行高。普通桌面样例预期约 100–125px/条；实际高度随长标题和标签自然增长，不以固定高度裁掉信息。标题最多两行；摘要桌面默认一行、窄屏最多两行。作者、发表时间与标签形成辅助行，回复数与批注数分开表述。

最新排序优先展示发表时间；最近活跃排序明确展示最近活动时间，并保留发表时间的完整可访问信息。时间规则统一，不把“发表于”偷偷改成“活跃于”。不为模拟图里的相对时间新增复杂实时计时器。

整行导航保持原生链接语义，作者、标签和跳转回复为独立链接。不新增第二份 tabindex，不用父级 click 拦截全部子操作。视觉截断不截断可访问名称，不依赖 hover 才能了解关键内容。

### 5.2 文案规则

保留当前操作需要的信息，删除氛围性说明、技术实现叙述和重复标题。隐私、数据损失、批注保护和冲突信息仍直接显示。

| 当前内容 | 处理 |
| --- | --- |
| “近来写下的文字”及社区氛围段落 | 紧凑标题与浏览工具栏 |
| 通知的“只属于你的消息” | 删除；保留通知标题、筛选、数量 |
| “编辑器会在后台维护 Markdown” | 从普通写帖流程移除 |
| 编辑页常驻“不顶到活跃首位” | 收到相关帮助中 |
| DOCX 本地解析/原文件不上传重复提示 | 合并；放在选择文件附近 |
| 格式丢失、未导入内容 | 就近显示原因及可执行动作；阻断和非阻断明确区分 |
| 批注保护导致无法保存 | 使用现有受影响范围/批注定位能力提供指引；不得只给抽象错误句子 |

## 6. 数据导航与搜索契约

### 6.1 真实分页

帖子、搜索、标签详情、个人帖子、个人动态和通知默认每页 **20 条**；不新增页容量选择器。后台沿用20条和原语义。总页数不足2页时不展示无用页码。

- 新建明确的分页查询入口，例如 `listPostsPage`，返回 `items、total、page、pageSize`。不要直接改变 `listPosts` 返回类型而遗漏消费者；迁移完普通列表后，检查旧入口是否仍有合法的有界用途，再决定删除。
- `COUNT` 与数据查询复用同一权限/状态/搜索/标签条件；多标签关联不能重复计数。当前页标签和计数批量获取，避免逐帖查询。
- 保持 D1 窄投影；不要把每种内容的全部字段加入一个巨大联查。新增批注计数按当前 revision membership 与既有 lifecycle 可见性定义聚合；后台计数不可直接用于社区。
- 回复数仍是普通回复数；批注数独立显示。若无法在当前批次正确获取批注计数，则先不展示它，禁止推算或混为“回复”。
- 最新排序采用 `publishedAt DESC, id DESC`；活跃排序采用 `lastActivityAt DESC, id DESC`。通知/动态同样补稳定 ID 次序。仅增加稳定的同时间排序，不改变活跃时间业务规则。
- page 使用严格正整数解析：缺失、非整数、负数、不安全整数回到1；正整数越界归到最后一页；无结果归到1。数据返回与URL指向应一致，规范化时保留合法筛选。
- filter/query/sort改变回到第1页；翻页保留其他参数。删除、隐藏、读状态变化后重新校准当前页，避免空的越界页。
- offset 分页适用于当前小型社区。活跃时间或未读集合在翻页期间变化，结果可能移动；不承诺快照一致性，不因此引入快照数据层。只有实际规模或连续阅读需求证明必要时再评估游标。

### 6.2 URL与恢复

| 列表 | URL状态 |
| --- | --- |
| 首页 | `?sort=active&page=2`，默认最新与第一页可省略 |
| 搜索 | `?q=关键词&page=2` |
| 标签详情 | 标签保留在路径，`?page=2` |
| 个人帖子/动态 | `?tab=activity&page=2`；切tab回到该tab第一页 |
| 通知 | `?tab=unread&page=2` |
| 后台 | 保留现有type/status/q/sort/from/to/page契约 |

进入帖子后浏览器返回必须恢复来源URL与浏览位置；显式“全部帖子”导航可回首页，但不能伪装为“返回原结果”。优先验证现有路由恢复，只有真实失效时增加小范围恢复逻辑。翻页可以定位结果区开头；返回列表不强制滚到顶部。

### 6.3 搜索与日期

继续采用显式提交，避免擅自改成实时远程搜索。输入非空即出现可访问清除按钮；清除立即生效、聚焦输入、重置分页，并保留页面适用的其他筛选。中文输入法组词期间不得误提交。社区搜索范围保持标题＋正文，样板对作者/标签的本地演示匹配不照搬。

统一搜索框的标签、占位、清除与提交语义；顶部保持紧凑，结果页可承载完整查询。避免两个输入框显示不同的已提交查询。

管理员日期筛选继续按北京时间。展示格式走同一格式化入口：本轮建议统一到 `Asia/Shanghai`，让相同内容在服务端、浏览器及后台显示同一时间；实施前核对既有数据均为时间点，并确认不改变持久化时间与日期筛选范围。日期选择器和简单单选沿用原生控件，平台弹层外观作为明确接受的差异。

### 7.1 PageHeader、Header与管理导航

PageHeader由一个h1、可选真实计数、右侧操作组成；标题26px，计数12–13px，横向gap16px，结束后留20px到工具栏。计数未知就省略。短页面不自动生成eyebrow和说明。手机允许操作转下一行；状态和主要按钮不截断成无意义省略号。

Header从左到右为：校徽/站名（回首页）、搜索、通知、写帖、头像菜单。沿用样板的克制结构，不强制插入一排全局文字导航。标签位于浏览页工具栏右端和账户菜单；管理后台只对管理员出现在头像菜单中，进入后台后左导航保持可见，窄屏转“管理导航”。

现有`SiteHeader`已经以`unreadCount`显示徽标，0不显示、1–99显示数字、超过99显示99+，可访问名称包含真实未读数。该能力明确保留；计数加载或失败不显示编造的数字，并保证铃铛点击有效。头像菜单也已有后台链接。本轮不增加通知下拉预览，不把这两项误写为从零新增功能。

后台移除“总/帖/回/批/答/员/志”的方框汉字图标，采用纯文字导航：总览、内容分组及四类内容、成员与白名单、操作日志。沿用43–44px行高、明确分组、左侧选中标记和浅绿底。不给每项再加一个装饰图标；正文含义由完整标签承担。

### 7.2 PostListItem、SearchField与Pagination

PostListItem的左区依次为标题、摘要、作者/时间/标签；右区为普通回复数、批注数。右区只显示有真实来源的数据，约占80–100px；空间不足时随元数据行重排，标题保留主要空间。每行上下padding初始18px，细底边，无外层浮起阴影；hover轻背景，链接焦点清楚。正文不设置强制相等高度。

SearchField使用真实label或aria-label，输入占满剩余空间，非空清除键放右侧，搜索图标非动作时aria-hidden。清除键至少24px且与相邻操作保持间隔；触摸变体44px。Enter提交，IME期间不提交。已提交查询和编辑中的输入分开管理，清除行为见6.3。

Pagination由“第a–b篇，共n篇”和页码导航组成；桌面两端排列，窄屏自然换行。显示上一页、当前页、当前页前后各1页、首末页，缺口用不可点击省略号；2页以内不制造省略号。当前页用aria-current=page、浅绿底和文字强调；无上一/下一页时为禁用非链接，不伪造href。每个数字目标桌面至少34×34px，触摸44×44px。零结果只显示空态，不显示“第1–0篇”。

### 7.3 编辑器与DOCX操作区

新建/编辑采用“页面操作区＋纸面”布局，弱化表单外壳。操作区左侧是“写帖子/编辑帖子”，中部是本地草稿状态，右侧是取消和发布帖子/保存修改；新建页附次级“导入DOCX”入口，手机可收入同区的更多操作。编辑既有帖子不提供暗示覆盖导入的入口。

操作区在文档中先占据空间，再sticky于Header下方；初始高度48px，容器跟随对应外框。Header高度变化时使用同一测量/token来源更新偏移，不硬编码多个相互矛盾的top。手机同样保留顶部操作，不再同时铺底部固定发布条；按钮可换行但不能挡住聚焦输入。原表单底部重复提交区删除，所有提交入口必须指向同一form/action和pending状态。

工具栏位于纸面标题下面，常规文档流，不新增第二条sticky工具栏。继续使用Milkdown现有工具栏/选择工具能力；本轮不擅自增加“预览”按钮，不改成另一套编辑器。当前没有独立手动“存草稿”操作，明确延续自动本地草稿，不新增会误导为服务器草稿的按钮。

标签放在标题之后、工具栏之前的紧凑单行字段，保留逗号分隔及最多5个规则；本轮不开发chip编辑器或自动补全。可显示已有tag视觉提示，但只有一个受控输入源。附件保留在正文之后的附件区域及既有上传入口；上传进度和失败不能折进不可见菜单。

恢复草稿、冲突和待撤下批注提示在操作区下方、相关内容之前，以完整提示面板显示；不塞入操作区造成持续增高，也不因顶部精简被隐藏。

DOCX预览操作区沿用样板“检查并导入＋文件信息＋重新选文件/确认导入”的顺序，可复用相同sticky定位能力。检查面板保留在右侧；窄屏切换后，阻断摘要及跳到待处理项入口在确认区附近可见。确认按钮的禁用理由就近显示，不能只用颜色表达。

### 7.4 回复区和批注线程

普通回复区与正文纸面第一列对齐，根级内容区最大净宽720px；不铺到批注侧栏下方。区头是“讨论＋真实数量＋回复文章”，根级输入打开后位于区头之后、回复列表之前。样板中的3条回复为示例计数，正式版取实际可见数。

普通回复继续采用根回复＋一层子回复，子回复桌面缩进24px、手机12px，不递归缩进。回复子回复时保留实际被回复人语义。所有子回复默认展开，本轮不增加长线程折叠或“加载更多”而破坏已有深链；已有内容全部可达。回复单条内容的编辑框仍在该条内容下方，不改业务层级。

已删除/隐藏根内容显示正常字重的中性占位，沿用lifecycle提供的准确句子；有权保留的他人回复继续显示。正文不可访问时不提供能绕过权限的动作。

批注卡片依次为作者/时间/来源、正文、回复批注/定位原文、单一回复输入、已有回复。padding约12–14px，内部主要gap8–10px，卡片间距14px；不重复选区原文、不放大大段标题、不把主回复按钮放在线程末尾。桌面正文13px/1.7；Sheet正文14px/1.7，时间和来源12px。只读编辑批注沿用同样阅读排版，移除全部写操作。

### 7.5 按钮变体与状态

| 变体 | 默认样式 | 场景 | 限制 |
| --- | --- | --- | --- |
| Primary | 绿底暖白字 | 发布、保存、确认导入等主要安全动作 | 每个操作区域一个主要动作 |
| Secondary | 纸面底、细描边 | 取消、重新选文件、次级流程 | hover轻绿；不与Primary同等强调 |
| Ghost/Text | 透明底、正常或品牌文字 | 更多、定位、辅助导航 | 保留明确点击范围和focus |
| Danger quiet | 透明或描边，危险色文字＋明确动词 | 列表删除、批量永久删除入口 | 不直接铺整块实心红；先进入确认 |
| Danger solid | 危险底、暖白字 | 最终删除/永久删除确认 | 只在确认区域出现；默认焦点为取消 |

pending保持原宽高、禁用重复操作，并提供可访问状态；disabled不响应、无位移动画，必要原因就近说明。后台0条选中时，批量操作区保留稳定高度，显示“选择当前页内容后可批量操作”；批量隐藏和永久删除按钮均禁用。选择后展示准确数量，清除选择后恢复，禁止将当前页解释成全部结果。

### 7.6 状态表面与空态文案

状态面板不使用巨型插画或额外营销说明。普通空态在结果区内以约32px上下留白展示一行核心句子和至多一个主要动作；错误面板仍容纳incident ID、重试及保留内容说明。

| 场景 | 核心句子 | 动作 |
| --- | --- | --- |
| 首页无帖子 | 还没有帖子，写下第一篇吧。 | 写帖子 |
| 搜索无匹配 | 没有找到匹配的帖子，试试更短的关键词。 | 修改搜索（聚焦并选中查询） |
| 标签详情无内容 | 这个标签下还没有可见帖子。 | 浏览全部标签 |
| 标签索引为空 | 还没有使用过的标签。 | 浏览帖子 |
| 通知全部为空 | 暂时没有通知。 | 浏览帖子 |
| 未读通知为空 | 没有未读通知。 | 查看全部通知 |
| 自己的帖子为空 | 你还没有发布帖子。 | 写帖子 |
| 他人的帖子为空 | 这位成员还没有可见帖子。 | 浏览帖子 |
| 个人动态为空 | 暂时没有可见动态。 | 查看该成员的帖子 |

清除搜索后并不等于“所有帖子”，搜索页进入“输入关键词搜索帖子”的未查询态；不要自动展示全站列表改变范围。

### 7.7 时间与来源

保留样板的绝对短时间路线，不增加自动刷新的“几分钟前”。列表当年用`M月D日 HH:mm`，跨年用`YYYY年M月D日 HH:mm`；“今天”可省略为统一绝对日期实现，不另建相对时间体系。文章详情、管理记录和历史版本直接显示带年的完整分钟时间。时区按6.3统一。

列表使用语义`time datetime`；完整时间供title及可访问名称读取，标题式提示不是唯一可获知途径，详情元数据直接展示完整值。Word来源时间明确标记原始来源，不能把导入时间标成作者发表时间。未提供时区或不完整的原始日期按现有导入语义处理，不猜测补造。

### 7.8 样板与规格的权威边界

样板决定整体视觉、信息主次、单列浏览、独立纸面、导入右栏和紧凑线程。本版补齐样板未覆盖的无批注状态、大视口、真实导航、编辑页、回复列表及危险状态，不修改样板来制造“原来就已批准”的假象。样板中依赖演示运行时的图标、模拟查询和按钮提示仍不能进入生产。

## 8. 必须保持的交互与数据不变量

### 8.1 阅读、批注与编辑

- annotation ID仍是正文、线程、connector、通知深链的稳定关系；禁止使用字符串搜索替代锚点。
- 跨段批注继续共享同一线程和多段标记；容器调整必须核对DOM查询范围、坐标系及首段锚点。
- 只有阅读页合法选区能创建批注；选区在弹窗、pending和失败期间继续可见。
- 正文hover只作局部反馈，点击/键盘/深链才滚动定位。视觉样板未模拟完整connector，不代表移除连线。
- 卡片防重叠、图片加载后重测、缩放与窗口变化继续有效；普通scroll不触发逐帧React更新或Markdown重新解析。
- 编辑批注栏继续只读。边界破坏确认、内部编辑、Undo/Redo、IME、跨段行为、剪贴板去标记及服务端重新验证全部保留。
- 删除/隐藏占位不连带移除仍可见的其他成员讨论。

### 8.2 写作与导入

- 保存的目的地仍是帖子详情；取消遵循原流程；不以统一外观为由改成返回列表。
- IndexedDB草稿恢复、上传失败后保留内容、过期/权限撤销指引与冲突阻断继续存在。
- 忙碌按钮预留最长标签或复用叠放标签，不让“保存中”“等待上传完成”等文案推移其他操作。
- 导入保持Worker解析、文件限制、取消、Preview恢复、Word署名、关联用户不冒充作者、临时资产和重复提交幂等。
- 弹窗挂在全局portal；键盘和手机虚拟键盘不能遮住当前输入及关键操作。原始DOCX不会上传的提示不被移除。

### 8.3 管理与反馈

- 保留后台当前页选择范围、批量上限20、部分失败结果和永久删除语义。
- 内容类型仅在左侧导航出现，不重新添加头部类型segment。
- 表格的固定列、固定表头、预览、完整内容查看和操作都可达。若缩窄操作列，必须先提供完整的更多操作入口；不得直接裁剪动作。
- 后台保留既有滚动契约，逐面板验证总览、成员、日志、历史；不把社区表单套入后台的全视口锁定。
- 错误沿用安全文案和incident ID，不用toast替换需要持续处理的错误，也不新增原生alert/confirm。

## 10. 验收与测试策略

### 10.1 视觉与响应式矩阵

| 场景 | 核心检查 |
| --- | --- |
| 1440×900桌面 | 首页工具栏和至少5条普通测试帖子可见；首条内容不被说明区推到折叠以下 |
| 1280×800笔记本 | 正文＋批注在实际组合宽度足够时显示；后台主区不被摘要挤压 |
| 1024×768/768×1024 | 批注进入Sheet但入口不丢；导入检查重排；无整个页面横向溢出 |
| 390×844手机 | 搜索可展开、头像及主操作可用；标题和标签自然换行；Sheet内容和操作可达 |
| 320px窄屏、200%文本/页面缩放 | 控件可换行；正文可读；固定区域不裁剪；表格横向滚动仅在表格内 |
| 新批注组合阈值前后各1px | CSS、JS、connector和Sheet模式一致；切换时不重复线程和丢失焦点 |
| 外框对齐：首页/通知/设置/详情/后台 | Header与PageHeader及工作区外框同边缘；按3.2明确的内列可以内缩；无1320顶栏套1800后台 |
| 同宽度有批注/无批注文章 | 纸面和回复区的横向起点、净宽一致；无批注时无不可见可聚焦元素 |
| connector默认/点击/键盘/深链 | 默认无全量连线；只显示当前有效线程；hover无滚动或线束 |
| Windows实际字体/100%与200%缩放 | 记录命中的字体；检查桌面13px和Sheet14px线程，不以macOS样例代替 |
| 长标题/5个标签/长作者名/长错误 | 无重叠、漏操作或固定高度截断 |
| 无批注/1条/密集跨段/多回复 | 相同正文尺度；连线与卡片稳定；手机线程完整 |
| 导入大量警告/长作者名/图片 | 正文仍是主要表面；提醒可分类处理；确认操作可达 |

首页首屏条数只对固定的普通测试内容和指定视口验收，不强迫所有真实帖子相同高度。批注密度不通过把正文和回复无限缩小来达标。

### 10.2 必要的行为检查

- 分页：0/1/20/21/40/41条；重复排序时间；标签多重关联；搜索无结果；页码非法与越界；隐藏/删除后缩页；未读变少后的页码恢复。
- 导航：筛选后进入详情再返回；翻页后刷新/复制URL；个人页切tab；通知跳转正文与批注；直接访问旧URL。
- 写作：长文输入、中文IME、上传失败、保存pending、草稿恢复、冲突、取消；guard确认→撤销→保存。
- 批注：跨段选择、保持选区、点击与键盘定位、hover不滚动、长线程、防重叠、图片加载后几何、Sheet切换。
- DOCX：使用仓库已有真实fixture完成选择→解析→预览→处理提醒→编辑→提交→详情→再次编辑；不为UI重构新造解析器。
- 后台：筛选、翻页、选择当前页、批量部分失败、隐藏/恢复/永久删除确认；切换成员/日志等面板后无滚动裁切。

只为分页、可见性计数、模式阈值等有真实分支和回归风险的变化补针对性测试；优先复用现有fixture与测试设施。不为每个颜色、间距或class名写单元测试。

### 10.3 流畅与可访问性

记录同一环境、相同内容下的迁移前后结果；不把样板或主观感觉当生产性能证据。重点检查：路由切换立即反馈、已有页面壳稳定、局部骨架与完成态匹配、批注滚动不新增持续计算、普通阅读不提前加载完整编辑器。

键盘可到达所有动作；焦点不被sticky区域遮挡；dialog/Sheet可关闭并恢复焦点；搜索和表单均有名称及错误关联；正常文字至少4.5:1对比度，非文字控件按适用标准验证；触摸目标和缩放可用。各路由标题不包含用户无权读取的帖子正文或历史内容。

### 10.4 工程检查与报告

每批只运行直接相关检查；最终运行项目要求的格式、类型、lint、测试和构建门槛。当前参考命令：`npm run format:check`、`npx tsc --noEmit`、`npm run lint`、`npm test`，以及严格设计审计。`npm test`当前已包含构建和渲染检查，除非发生新的变更或发布流程需要，不重复无意义的全量构建。

实施阶段安排真实浏览器视觉/交互QA，并遵守当前Sites预览能力和用户授权范围；环境不支持时明确记录缺口，不能把静态审计零项写成浏览器验收通过。本次方案整理不运行生产构建、浏览器或部署。

## 12. 风险、回退与实施起点

| 风险 | 防护与回退方式 |
| --- | --- |
| 全局CSS影响未迁移页面 | 分批迁移；每批检查代表性兄弟页面；修改原规则并清除淘汰声明 |

| 精简顶部时误删保护信息 | 依据文案分类，只去重复与氛围说明；数据风险和阻断保留 |
| 后台缩宽或滚动锁定造成裁剪 | 延续既有shell契约，逐面板检查；摘要退让主表格 |
| 演示细节被当作生产功能 | 明确标注样板范围；真实数据、完整线程和现有编辑器必须接回 |

按任务提交回退，避免把视觉与权限/生命周期重写混在一起。原则上无需数据迁移；确需索引时另建可审查迁移。代码回退不应撤销用户已经产生的内容或更改线上访问范围。

开始实施时：获取最新远端、核对干净工作树与现行AGENTS，创建实施分支，将本方案纳入仓库，再执行T01。无需重新讨论已经认可的视觉方向；尺寸在真实内容验证中微调，重大产品范围或高风险业务变化另行明确。发布和访问范围按照届时的用户指令执行，本文件不代表已部署或已授权改变访问范围。
