# 知临中学 Playwright 行为测试方案

日期：2026-09-06  
分支：`feat/playwright-behavior-tests`  
状态：已实施，等待可用 Chromium 环境完成运行验收

## 1. 决策

在不迁移现有 `node:test` 测试的前提下，引入一套小型 Playwright 浏览器行为测试。

测试按产品能力组织，不按历史 Bug、页面组件或实现文件组织。一个功能由少量长期稳定的用户旅程保护；修复 Bug 时优先补强已有旅程，不默认增加永久回归测试。

首版只使用 Chromium、一次性本地 Miniflare D1/R2、三个成员身份和一个未受邀身份，保留 8 个 spec 文件、18 条行为测试。Playwright 不连接 Cloudflare 远端，不访问或修改正式站数据。

## 2. 当前基线

当前项目已经使用 Node 内置测试运行器：

- `npm run test:unit`：377 项，376 通过、1 项因缺少可验证 Word Online fixture 跳过、0 失败。
- `npm run build`：通过。
- `tests/rendered-html.test.mjs`：11 项构建产物检查全部通过。
- 现有测试擅长领域规则、Markdown/Annotation AST、DOCX 解析与安全、SQLite 事务和迁移、幂等、IndexedDB、Worker 与构建契约。
- 当前没有直接安装或配置 Playwright，没有真实浏览器自动化，也没有提交时自动执行的 CI 工作流。

现有测试不应整体迁移到 Vitest、Jest 或 Playwright。Playwright 只补充浏览器与完整应用链路的可观察行为。

## 3. 目标与非目标

### 3.1 目标

1. 验证真实浏览器中的点击、输入、选区、焦点、滚动、响应式布局、导航和下载。
2. 验证页面、Server Action/API、D1、R2 与重新渲染组成的完整用户链路。
3. 每个主要产品能力保留 1–3 条稳定行为测试。
4. 失败时提供足够诊断信息，但不以自动重试隐藏不稳定测试。
5. 逐步替换已经被浏览器行为覆盖的脆弱源码字符串断言，避免测试只增不减。

### 3.2 非目标

首版不做：

- 按历史 Bug 建立一条条独立回归测试。
- 穷举已有单元测试覆盖的领域状态排列。
- 多浏览器兼容矩阵。
- 像素级截图或视觉快照测试。
- 通用 Page Object 框架。
- 对 React 组件层级、CSS 类名、内部函数调用或 Server Action 实现作断言。
- 在正式 Sites 部署上执行发布、删除、标记已读或管理员操作。
- 以 Playwright 替代人工视觉验收。

## 4. 测试分层

| 层级        | 责任                 | 典型验证                                                   |
| ----------- | -------------------- | ---------------------------------------------------------- |
| `node:test` | 领域行为与技术不变量 | AST、状态机、权限、事务、迁移、查询、DOCX 安全、幂等       |
| Playwright  | 浏览器中的产品行为   | 发布、编辑、框选、导航、焦点、刷新持久化、下载、响应式模式 |
| 人工验收    | 主观和复杂视觉质量   | 字体观感、密集内容、不同设备真实手感、整体审美             |

一个行为只在最合适的层级详细验证。Playwright 只选择代表性完整链路，不重复单元测试的组合爆炸。

## 5. 稳定测试规则

### 5.1 测试用户行为，不测试实现

允许断言：

- 用户能看到什么、能否操作、操作后到达哪里。
- pending、失败、冲突、删除、隐藏和不可用状态是否明确。
- 输入在失败、刷新或冲突时是否按合同保留。
- 刷新后数据是否仍存在。
- URL 是否表达并恢复筛选、排序、分页和选中目标。
- 通知是否到达正确对象并定位到稳定目标。
- 焦点、Sheet、Dialog 和键盘退出是否符合交互合同。
- 图片和附件是否可见、可下载。

禁止断言：

- 组件名、Hook、内部函数或调用次数。
- CSS 类名、源码字符串、文件引用关系。
- DOM 必须嵌套几层。
- Server Action、RSC 或 API 的内部传输格式。
- 精确像素、颜色值和整页截图。
- 数据库具体执行了哪一条 SQL。

数据库只用于准备场景，不作为浏览器测试的主要断言面。除非结果无法通过产品界面或公开下载行为观察，否则不直接查询数据库判断通过。

### 5.2 选择器

按以下顺序选择元素：

1. `getByRole()` 与可访问名称。
2. `getByLabel()`。
3. 用户可见的稳定文字。
4. 产品本身已有的稳定业务 ID，例如批注深链 ID。
5. 只有在没有合理语义入口时才使用最少量 `data-testid`。

如果关键控件没有稳定语义选择器，优先补充 `aria-label`、label 或正确角色，使真实用户和测试同时受益；不为测试复制一套隐藏 DOM。

### 5.3 时序

- 使用 Playwright 自动等待和基于结果的 `expect`。
- 禁止固定 `sleep` 或人为延时等待页面“差不多完成”。
- 只等待用户能观察到的目标状态、URL 或焦点。
- 动画仅在确有行为意义时验证完成状态，不验证逐帧过程。

## 6. 本地数据与安全边界

### 6.1 一次性 Miniflare 状态

每次完整 Playwright 运行创建一个专属临时目录：

1. 创建精确、可验证的临时目录。
2. Cloudflare Vite 插件通过 `E2E_STATE_DIR` 将 `persistState` 指向该目录。
3. 对本地 D1 依次应用仓库现有 `drizzle/*.sql` 正式迁移。
4. 插入最小测试种子数据。
5. 本地应用和 Playwright 共享该 D1/R2 状态。
6. 测试结束后停止应用，再删除这个精确临时目录。

D1 仍通过 `env.DB` 使用 Cloudflare D1 API，底层由本地 SQLite 承载；R2 仍通过 `env.BUCKET` 使用本地对象存储模拟器。测试不使用自制内存 Repository，也不联系 Cloudflare 远端。

第一版整轮共用一个全新数据库，固定 `workers: 1`。每条测试只修改自己的场景记录，以固定 ID 或场景前缀隔离；不依赖前一条测试的成功，不通过逐项清理恢复基线。整轮完成后直接丢弃临时状态。

如果未来单线程执行时间实测不可接受，再按 Playwright worker 分配独立状态目录；首版不提前实现并发隔离。

### 6.2 身份

种子数据包含：

- `admin@example.test`：唯一管理员。
- `author@example.test`：作者。
- `reader@example.test`：受邀普通成员。
- `outsider@example.test`：没有 allowlist 记录，仅用于拒绝访问场景。

浏览器上下文只对本地应用设置 Sites dispatch 使用的认证请求头。不同身份使用不同 BrowserContext，不增加测试登录页面、后门账号或生产可调用的测试 API。

### 6.3 硬性安全阻断

Playwright 启动前必须同时满足：

- Base URL 主机属于明确的本地允许列表，例如 `localhost`、`127.0.0.1` 或 Work 内部 `terminal.local`。
- 当前运行具有显式 E2E 模式标记。
- `E2E_STATE_DIR` 存在且位于本次创建的临时目录下。

遇到以下情况立即退出，不允许降级继续：

- Base URL 是 `*.chatgpt.site`、其他 HTTPS 站点或未知主机。
- 没有独立临时状态目录而将要复用普通 `.wrangler/state`。
- 启动命令要求 `--remote` 或远端 Cloudflare 凭据。
- 测试种子和迁移没有成功完成。

正式站以后如需自动冒烟，只能另建只读测试命令；写入型 Playwright 套件永远不接受正式站 URL。

## 7. 场景种子

种子脚本只表达场景，不复制生产业务实现。需要通过用户行为创建的数据由 Playwright 自己创建；为了让测试独立或直接进入复杂状态而预置的数据使用固定 fixture。

初始场景包括：

- 三个已注册用户、allowlist 和管理员配置。
- 普通帖子、带图片/附件帖子、带两层普通回复的帖子。
- 可安全编辑、可触发端点确认和跨段的批注帖子。
- 有批注回复、历史 revision、用户删除和管理员隐藏状态的独立帖子。
- 25 条用于分页、搜索、标签和稳定排序的帖子。
- 指向普通回复、批注和失效目标的通知。
- 独立的管理员隐藏、恢复、批量操作和永久删除目标。

DOCX 测试继续使用仓库已有的真实 fixture，尤其是带三段跨段批注的 owner fixture；不把解析后的预期结果手工复制为另一套测试文档。

## 8. 首版行为目录

首版计划 8 个 spec 文件、18 条测试。测试标题采用用户行为，不包含 Bug 编号、提交 SHA 或实现名称。

### 8.1 `e2e/access-profile.spec.ts`：2 条

1. **管理员邀请后，新成员完成首次资料并进入社区**
   - 未受邀身份访问时得到明确拒绝。
   - 管理员添加该邮箱。
   - 同一身份重新访问后进入 onboarding，完成资料并进入首页。
   - 不断言 allowlist 表结构或鉴权函数调用。

2. **成员修改资料和头像后，刷新仍显示新资料**
   - 修改显示名和头像。
   - 等待成功反馈并刷新。
   - Header 与个人页显示新资料，头像资源可读取。

### 8.2 `e2e/posts.spec.ts`：3 条

1. **作者发布带标签、正文图片和附件的帖子后可以完整阅读**
   - 填写标题、Markdown 内容和标签。
   - 上传一张正文图片及一个附件。
   - 发布按钮 pending 时不可重复提交。
   - 成功进入帖子页；刷新后正文、标签、图片和附件仍存在，附件可以下载。

2. **作者编辑帖子后，成员看到新内容和编辑状态**
   - 从帖子页进入编辑页，确认服务端正文已经载入。
   - 修改标题和正文并保存。
   - 作者和普通成员刷新后都看到新内容及编辑状态。

3. **两个页面并发编辑时，不静默覆盖且保留本地内容**
   - 两个作者页面从同一 revision 开始编辑。
   - 页面 B 先保存，页面 A 再保存。
   - 页面 A 得到明确冲突选项，本地正文仍在。
   - 选择线上版本后内容更新；取消选择不会产生额外 revision。

### 8.3 `e2e/discussion-notifications.spec.ts`：2 条

1. **成员可以回复帖子和另一条回复，讨论始终保持一层并通知直接对象**
   - `reader` 回复作者帖子。
   - `author` 回复该回复。
   - 页面上两条回复处于同一视觉层级，并保留“回复谁”的关系。
   - `reader` 收到通知，打开后定位并高亮目标回复。
   - 删除被依赖的根回复后显示必要占位，子回复仍可读。

2. **提交失败保留回复内容，恢复后重试只发布一次**
   - 输入回复后将浏览器切换为离线再提交。
   - 页面显示可恢复失败，输入内容仍在。
   - 恢复网络并重试。
   - 页面只出现一条新回复，不依赖内部 submission key 作断言。

### 8.4 `e2e/annotations.spec.ts`：4 条

1. **同段和连续跨段选区都能创建独立批注**
   - 通过真实鼠标拖拽产生选区，触发完整 pointer/selection 事件顺序。
   - 分别创建一个同段批注和一个连续跨段批注。
   - 可见正文不改变，两个讨论线程独立存在。

2. **批注只由点击或键盘激活，悬停不自动滚动正文**
   - 悬停批注范围时只产生局部反馈，正文和侧栏滚动位置不改变。
   - 点击范围后打开对应线程并显示单一活动关联。
   - 键盘激活具有相同行为。

3. **批注回复通知正确对象，删除后按依赖关系保留讨论**
   - 回复根批注和另一位成员的批注回复。
   - 回复列表保持一层，单一输入区位于根批注后。
   - 通知到达直接目标；删除根批注后，根据现有成员讨论显示占位或移除锚点。

4. **批注正文内部可直接编辑，破坏端点必须确认**
   - 在批注内部插入文字，保存过程不弹确认，批注继续有效。
   - 删除受保护端点时出现一次确认。
   - 取消后正文和批注不变；再次操作并确认后保存，当前版本撤下该锚点。
   - 管理员历史版本仍能看到对应旧状态。

### 8.5 `e2e/docx-import.spec.ts`：2 条

1. **真实 DOCX 可以生成可恢复 Preview 并导入为完整帖子**
   - 选择仓库真实跨段批注 fixture。
   - 显示分阶段解析进度、正文、批注、图片和必要警告。
   - 刷新导入页并恢复 24 小时内 Preview。
   - 确认导入后进入新帖子，正文和跨段批注可读。

2. **导入帖子可以继续编辑，保存后正文和批注保持完整**
   - 直接打开独立的已导入帖子 fixture。
   - 编辑器正文在首次可操作时不为空。
   - 修改普通正文并保存。
   - 刷新后修改存在，未被修改的批注仍能定位和讨论。

DOCX 的非法 ZIP、XML、图片限制、评论图结构和每个生产者差异继续由 `node:test` 覆盖，不在浏览器中重复穷举。

### 8.6 `e2e/discovery.spec.ts`：1 条

1. **搜索、标签、排序和分页由 URL 表达并可由浏览器返回恢复**
   - 从首页切换最新/活跃排序并进入第二页。
   - 执行中文搜索，进入第二页并打开帖子。
   - 浏览器返回后恢复原查询和页码。
   - 从标签进入列表时只显示该标签结果。
   - 不在浏览器层重复验证所有 20 条分页边界和 SQL 排序组合。

### 8.7 `e2e/lifecycle-admin.spec.ts`：3 条

1. **作者删除帖子后保留必要讨论，管理员恢复后正文重新可见**
   - 删除含其他成员公开回复的帖子。
   - 同一 URL 显示作者删除占位和仍可读讨论，不泄露正文。
   - 管理员恢复后普通成员重新看到正文。

2. **管理员可以通过筛选执行隐藏、恢复、批量操作和永久删除**
   - 使用内容类型、状态、搜索和日期筛选找到固定 fixture。
   - 隐藏和恢复更新当前状态及审计摘要。
   - 当前页选择计数准确，批量操作只影响当前页目标。
   - 对独立 fixture 执行永久删除后，列表和公开页面都不再提供该内容。

3. **管理员恢复历史版本时生成新版本并恢复完整状态**
   - 选择旧 revision 并确认恢复。
   - 恢复后帖子正文、附件和批注状态与所选历史版本一致。
   - 历史时间线仍保留原版本和新恢复版本。

### 8.8 `e2e/responsive.spec.ts`：1 条

1. **批注阅读和全局导航在桌面、中间宽度和手机保持同一语义**
   - 桌面宽度使用批注侧栏，点击正文范围定位线程。
   - 手机宽度使用 Bottom Sheet，关闭后焦点回到触发范围。
   - 中间宽度下搜索、写帖、通知和头像仍有可操作入口，不产生页面级横向滚动。
   - 不断言精确断点、像素坐标或完整截图。

## 9. Playwright 配置约束

首版配置：

- 浏览器：Chromium。
- `workers: 1`。
- `retries: 0`，不通过重试掩盖 flaky test。
- 只在失败时保留 trace 和截图。
- 成功测试不录制视频。
- 禁止视觉 snapshot。
- 默认超时保持短而现实；只有 DOCX 导入使用有依据的独立上限。
- Playwright 接受显式本地 Base URL，不自行推断或部署 Sites 生产版本。

在 ChatGPT Work 中执行浏览器验证时，遵守 Sites 的 supervised preview 流程；在普通本地或未来 CI 中，由 E2E 包装脚本启动同一个 Cloudflare Vite 本地运行时。两者必须共享相同的临时状态与安全阻断。

## 10. 建议文件布局

```text
playwright.config.ts
e2e/
  fixtures.ts
  seed.ts
  access-profile.spec.ts
  posts.spec.ts
  discussion-notifications.spec.ts
  annotations.spec.ts
  docx-import.spec.ts
  discovery.spec.ts
  lifecycle-admin.spec.ts
  responsive.spec.ts
scripts/
  test-e2e.ts
```

不建立 `pages/`、`models/`、`drivers/` 等通用抽象目录。只有满足以下条件的操作才能进入共享 helper：

- 至少有两个功能文件需要相同行为。
- 该行为本身是稳定产品语义，例如创建指定身份的 BrowserContext、选择真实正文范围。
- 提取后不会隐藏测试正在执行的关键用户步骤。

## 11. 命令与运行门槛

计划新增：

- `npm run test:e2e`：创建一次性本地状态并运行全部 Playwright 测试。
- `npm run test:e2e -- annotations`：开发期运行相关功能文件。
- `npm run test:e2e:headed`：本地可视化调试，不用于发布门槛。
- `npm run test:release`：现有 `npm test` 加完整 Playwright 行为套件。

运行原则：

- 修改单一功能时，先运行对应 `node:test` 和对应 Playwright spec。
- 公开发布包含产品代码的版本前运行完整 `test:release`。
- 纯文档、Git 或不影响运行结果的记录更新不运行 Playwright。
- 仅修改样式时运行直接相关响应式/交互 spec 与人工视觉检查，不机械运行无关 DOCX 或管理员写入旅程；公开发布前再跑完整门槛。
- 第一阶段不增加 GitHub Actions。`origin` 仍是权威源码，GitHub 只是按需镜像；在镜像不同步的前提下增加 GitHub CI 不能形成可靠门禁。

## 12. Bug 与新增测试准则

新增永久测试必须满足至少一项：

1. 新增了用户可见产品能力。
2. 既有能力增加了新的持久状态、权限边界或恢复路径。
3. Bug 证明已有功能旅程没有观察一个重要合同。

处理 Bug 时：

1. 找到它所属的功能 spec。
2. 如果已有旅程理论上应覆盖，先修正操作或断言，使其真正观察该行为。
3. 如果是新的稳定行为，在同一 spec 增加或拆分一条测试。
4. 不创建以 Bug 描述、工单号、日期或提交命名的测试文件。

示例：DOCX 帖子编辑正文空白应强化“导入帖子可以继续编辑，保存后正文和批注保持完整”，而不是新增 `docx-blank-editor-regression.spec.ts`。无论未来根因位于序列化、草稿恢复还是编辑器初始化，这条功能合同仍然成立。

以下变化默认不增加 Playwright 测试：

- 组件拆分、函数改名、状态管理重构。
- 不改变行为的 DOM 层级调整。
- 普通文案和视觉微调。
- 已由领域测试完整覆盖、且不会改变浏览器链路的内部规则。

## 13. 现有测试收敛

Playwright 引入后不允许只叠加、不清理。

1. 建立现有读取源码/构建字符串测试与新行为测试的对应表。
2. 浏览器已经直接验证的 CSS 类、组件引用、按钮源码和固定文案正则应删除。
3. 保留真实领域函数、SQLite、DOM 算法、Worker、IndexedDB、迁移和安全测试。
4. `rendered-html.test.mjs` 保留部署产物必须满足的少量技术合同，例如 Worker 不依赖 DOM、关键鉴权入口和安全元数据；不再承担可由浏览器验证的布局和操作存在性。
5. 每批删除前先确认新行为测试已经稳定通过，不做一次性大清洗。

目标不是减少测试数字，而是让每条测试拥有清晰责任，避免同一行为同时被源码正则、构建字符串和浏览器旅程重复锁死。

## 15. 验收标准

方案实施完成必须同时满足：

1. 8 个功能 spec、18 条行为测试全部通过。
2. 任一 spec 可以单独运行。
3. 连续运行两轮不会复用上一轮 D1/R2 状态。
4. 写入型套件面对正式域名会在启动浏览器前失败。
5. 测试代码不读取产品源码作正则断言。
6. 没有精确视觉 snapshot、固定 sleep 或自动重试。
7. 选择器以角色、label 和可见行为为主。
8. 现有 377 项领域测试不迁移，相关测试保持通过。
9. 已被浏览器行为完整替代的脆弱源码断言得到有依据的收敛。
10. `AGENTS.md` 明确：新 Bug 不自动获得独立回归测试，先补强功能合同。
11. 测试失败不会触发正式部署、远端 D1/R2 或外部副作用。

## 16. 已接受的首版限制

- Chromium 通过不能证明 Firefox/WebKit 全部兼容；出现真实跨浏览器需求后再增加目标浏览器。
- Miniflare 不能证明 Cloudflare 远端所有基础设施行为完全一致；正式发布仍需构建和少量人工冒烟。
- 不做像素截图意味着整体视觉漂移仍依赖 DESIGN、UX-CONTRACT、静态审计和人工验收。
- 单线程优先稳定性而非速度；只有实测运行时间影响开发时才增加并行隔离。
- 身份请求头只验证 dispatch 之后的站内授权行为，不自动化第三方 Sign in with ChatGPT 页面本身。

这些限制不削弱首版目标：用最少、稳定、可维护的浏览器旅程验证知临中学真正向用户承诺的功能行为。
