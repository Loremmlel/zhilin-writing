# SQL 参数上限与往返审计

## 事故与修复

《高三随笔 I》当前锚点达到 101 条后，阅读页把全部批注 ID 展开为回复查询的 101 个参数，超过 D1 单语句 100 参数上限。改为关联 `post_annotation_anchors`、按一个帖子 ID 过滤；根批注与回复合在一次只读 batch。保留访问权限、当前锚点范围、作者、排序、删除/隐藏占位。

## 全部 ID 列表查询的检查结果

| 位置                     | 结果                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| 批注线程读取             | 改 JOIN；参数不随批注数增长                                                         |
| 历史版本的资源读取       | 改 revision_asset_refs 子查询；快照关联读取合为一次 batch                           |
| 恢复历史批注和导入回复   | 改版本状态表子查询；仍逐项验证归属与缺失，不放宽恢复校验                            |
| 发布/编辑帖子资源校验    | 外部 ID 数组用一个 JSON 绑定参数；保留资源归属、删除和 GC 占用校验                  |
| 用户动态的回复对象       | 直接 LEFT JOIN，删除单独的用户 ID 收集和补查                                        |
| 永久删除批注回复         | 事件 ID 留在子查询中，省去预读取且没有事件数量参数上限                              |
| 其它永久删除             | 已使用子查询，保持删除次序及整批事务                                                |
| 首页、通知、动态关联补查 | ID 来自固定每页 20 条；参数有界，保留现有 batch                                     |
| 标签                     | 输入最多 5 个；参数有界                                                             |
| 版本边界                 | 固定 2 个版本 ID 与 1 个帖子 ID；参数有界                                           |
| R2 未追踪资源扫描        | 每页最多 90 个 key；参数有界，保留删除前新鲜检查                                    |
| DOCX 原生 SQL            | 查询按 100 个参数分块，多行 INSERT 按列数计算块大小；已有上限保护，保留原有原子提交 |

## 减少数据库往返

以下是代码路径的调用次数，不是线上延迟承诺：

| 读取步骤                             | 之前 | 现在                          |
| ------------------------------------ | ---- | ----------------------------- |
| 批注线程（含独立读取帖子；有批注时） | 3    | 2；同页帖子缓存命中时为 1     |
| 新增/删除/审核批注的三项快照         | 3    | 1                             |
| 编辑帖子三项当前状态                 | 3    | 1                             |
| 完整历史快照（有资源时）             | 5    | 2                             |
| 版本间批注变化读取（边界查出后）     | 3    | 1                             |
| 删除/隐藏后的活动时间计算            | 4    | 1                             |
| 永久删除帖子的五项计数               | 5    | 1                             |
| 永久删除批注的上下文                 | 4    | 1                             |
| 每项资源 GC 引用计数                 | 3    | 1；SQL 聚合代替传回所有引用行 |

保留需要前一结果的读取、分页越界纠正、鉴权和写入守卫。没有增加全局缓存、索引、表结构变更或改动线上内容。

## 验证范围

`tests/platform/database-limits.test.ts` 用完整迁移后的 SQLite 执行实际生产服务函数，运输层对每条语句检查 100 参数和 100 列限制。覆盖：第 100→101 条批注创建与读取、120 条 Word 回复、120 个附件、历史快照与恢复、权限隔离、撤下锚点、资源越权/缺失、批注回复/批注/帖子永久删除及相关内容保留、GC dry-run。另检查读取关键步骤的往返预算。

这不是生产 D1 的全套限制模拟，也不保证任意规模：超大写入事务、正文大小和 Worker 运行配额仍受平台限制。本次处理的是已发现的无界 SQL 绑定参数和相关读取开销。
