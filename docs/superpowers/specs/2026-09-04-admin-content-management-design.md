# 管理员内容管理增强设计

**日期：** 2026-09-04  
**范围：** `/admin` 内容列表。DOCX 格式导入增强已取消，不在本次范围内。

## 决策

- 继续使用原生语义 `<table>`，由共享 `AdminContentTable` 统一列、行和选择框；不引入第三方 DataGrid。
- URL 保存内容类型、状态、关键词、排序、起止日期和页码。状态支持 `all|normal|deleted|hidden`；日期是北京时间的自然日闭区间。
- 帖子和普通回复按发布时间筛选；批注和批注回复按 `source_created_at ?? created_at` 筛选、排序和显示。
- 多选只覆盖当前页，最多 20 条，不提供“选择全部搜索结果”。批量动作只有隐藏和永久删除；已经隐藏或已经不存在的记录计为跳过。
- 管理页占满站点 Header 下方的剩余视口，页面本身不滚动。内容表格同时拥有纵向和横向滚动；表头、选择列和操作列保持可见。成员、日志和总览在主面板内部滚动。
- 内容预览行固定高度；批注正文和原选文、批注回复正文和引用分别占固定两行，超出内容裁剪。操作保持单行，操作列固定在右侧。

## 永久删除合同

永久删除仅限管理员，必须使用应用自有确认弹窗，明确“不可撤销”，每个目标写入不含原文的审计记录。重试已经完成的目标是安全 no-op。

| 目标         | 删除范围                                                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 帖子         | 帖子、普通回复、批注与批注回复、历史版本、导入批次、通知、动态、标签关系和资源引用。资源元数据解除帖子关系，无引用的对象由现有 GC 异步回收。 |
| 顶层普通回复 | 顶层回复及其整条普通回复线程；删除相关通知与动态。                                                                                           |
| 嵌套普通回复 | 只删除目标；后代的 `reply_to_reply_id` 清空。                                                                                                |
| 批注         | 删除整个批注讨论、快照关系、通知与动态；从当前正文和所有历史版本中移除该 ID 的 Annotation 指令，保留可见正文。                               |
| 批注回复     | 只删除目标及其快照、通知和动态；后代的 `reply_to_reply_id` 清空。                                                                            |

保留既有管理员审计历史。删除回复或批注讨论后，所属帖子的 `last_activity_at` 必须从剩余可见内容的原始发表时间重新推导，不能使用操作时间。

## 反馈与失败

- mutation 采用悲观更新；pending 时阻止重复提交。
- 批量结果显示处理、跳过、失败的准确数量。部分失败保留弹窗和事件编号，已经成功的结果刷新列表。
- 页码在筛选或删除后由服务端 clamp 到仍然有效的最后一页。
