# 请求性能探针

## 覆盖与读取

- Worker 统一覆盖页面、RSC 导航、Server Actions、API、上传/下载和经过 Worker 的图片请求。
- 浏览器用 Resource/Navigation Timing 收集同源请求（包括静态资源、fetch、XHR）；另外记录 fetch 拒绝、慢交互（40ms 起）和主线程长任务（浏览器支持时）。
- `Server-Timing` 与 `X-Request-Id` 提供请求编号。既有错误日志仍保留 incidentId，同时附带 requestId。
- D1 `performance_logs` 独立保存性能数据。管理员登录后访问 `/api/performance` 获取最近 200 条，或用 `?requestId=<编号>` 查询关联记录。普通成员不能读取。
- 不新增管理界面。排查时也可通过 Sites 的数据库只读工具读取该表。

## 指标口径

| 字段                                         | 含义与边界                                                                                                              |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| responseReadyMs / 浏览器 serverMs            | Worker 开始处理至返回响应头；不含到达 Worker 之前的代理、边缘鉴权、排队、冷启动等开销，也不等于流式响应完成             |
| streamEndMs                                  | Worker 开始至响应流被消费完、报错或取消；含流式生成、消费背压，不能视为纯 CPU 或纯网络时间                              |
| dbMs / dbCount                               | D1 调用累计墙钟时间与语句数，含数据库通信等待；批处理按一次往返累计时间、按语句数计数。并行调用的时间可相加超过请求时间 |
| r2Ms / r2Count                               | R2 get/head/put/delete/list 调用累计时间与次数；get 返回后的文件流传输在 downloadMs/streamEndMs 中                      |
| dnsMs / connectMs / tlsMs                    | 浏览器可观测的 DNS、建连与 TLS；connectMs 包含 TLS；复用连接或缓存时可为零                                              |
| ttfbMs                                       | requestStart 到 responseStart，含发送、网络与服务端等待                                                                 |
| downloadMs / durationMs                      | 首字节至响应结束 / 浏览器资源请求总时长；流式响应下载阶段也可能包含后端工作                                             |
| inputDelayMs / processingMs / presentationMs | 慢交互的输入排队、事件处理、下一次呈现延迟；不是异步操作完成时间，也不是整页 INP 汇总                                   |
| domInteractiveMs / domCompleteMs             | 相对于首次导航起点的文档阶段时间                                                                                        |
| observedAt                                   | 客户端观测时间；由客户端时钟提供，不用于计算跨端精确时间差                                                              |

服务端分别保存 `response_ready` 和有响应体时的 `stream_end` 记录；后者包含流式阶段完成后的数据库累计值。浏览器响应头只能得到前者的快照。请求在客户端缓存命中时可能复用旧响应头编号；结合 transferBytes、时间和服务端记录判断。资源响应状态不可用时，缺失/零值不代表成功。

诊断时先比较同一编号的 ttfbMs、serverMs 和服务端数据库时间，再看 downloadMs、stream_end 与慢交互/长任务。`ttfbMs - serverMs` 仅是网络与未计入服务端入口的开销估算，不能据此断言代理有问题。探针不会访问或测量代理内部节点。

## 开销与数据边界

- 全局硬上限 **5,000 条**，SQLite 插入触发器在同一事务删除旧记录；服务端两个阶段与客户端记录共同占用上限。与错误日志分开。
- 浏览器最多缓存 120 条，每 10 秒最多发送 30 条，一次只允许一个在途批次；离开/隐藏页面尝试 keepalive 发送一批。积压淘汰最旧记录，失败不重试，关闭页面可能丢失尾部记录。
- 上报接口不被探针记录，防止递归。每次上报须同源且已登录白名单成员，JSON 流式读取上限 24KB，最多 30 条，只接受已知字段和有限数值。
- 不记录正文、查询参数、文件名、SQL、邮箱、Cookie、请求体或任意异常文本。路径仅保留预定义路由形状，动态参数被替换。
- 服务端使用 waitUntil 写入；日志失败不会改变业务响应，也不会重试业务操作。响应流按需透传，不克隆、不预读全文。
- 平台直接返回、浏览器不支持的指标、跨域请求、未完成或被取消的尾部上报不保证覆盖。此方案用于有界诊断，不承诺完整审计或精确链路追踪。

## 验证

`node --experimental-strip-types --test tests/platform/performance.test.ts tests/platform/logging.test.ts`

## 2026-09-09 首轮优化与对比基线

- 优化前（北京时间 13:50–14:05）：210 条性能记录、57 个服务端请求；18 次帖子操作，17 次有浏览器计时。操作浏览器总耗时中位数 4,236.6ms，响应头就绪 1,472ms，响应流结束 2,245.5ms。7 次操作后额外页面请求，每次 43 条语句、浏览器耗时 1,997.1–2,329ms。
- 移除新增批注与批注回复成功后的显式 `router.refresh()`；保留 Server Action 的 `revalidatePath` 和随响应返回的更新页面。失败输入、成功清空与选区状态不变。
- 管理员配置已满足唯一管理员和旧 bootstrap 清理条件时仅查询，异常时仍原子执行原有修复批次。页面和布局鉴权使用 `vinext/cache` 的请求内缓存；Action/API 单独重新鉴权，不提前缓存修改前的用户资料供页面重渲染使用。
- `dbCount` 仍是语句数；新增 `dbTrips` 是数据库调用次数，一个 batch 只算一次。服务端 `operation` 区分 `annotation.create` / `annotation-reply.create`，仅使用固定标记。`.rsc` 请求先归一化路由再脱敏。
- 新旧数据共存；旧记录没有新指标，不能当作零。数据库累计时间包含并发，不与端到端时间相加。下一轮比较同类操作与相近文章规模，单独观察网络波动。
- 鉴权行为检查纳入 `tests/access/auth-access.test.ts`：使用真实 SQLite 和当前框架请求缓存，验证初始化修复、稳定状态零写入、并发身份隔离及下一请求权限撤销。此检查不等同于浏览器验收。

## 第二轮查询优化

- 新增批注仅读取需要的帖子行，不再读取标签和附件。
- 阅读页和批注线程共享请求内的帖子读取；讨论状态的三项查询作为一个 D1 batch 执行，保留原有生命周期判断。标签、附件和状态读取并行；批注回复的目标用户随 JOIN 一起读取。
- 服务端新增 `dbSqlMs`、`dbMetaCount`、`dbRowsRead`、`dbRowsWritten`、`dbAttempts`、`dbRegion`。SQL 耗时优先使用 D1 `meta.timings.sql_duration_ms`，缺失时使用 `meta.duration`；不记录 SQL 和绑定值。
- 这些元数据只覆盖返回 D1Result 的调用。ORM 的 `raw()` 读取没有 meta，不额外执行查询来获取它，也不改变返回数组语义。必须同时检查 `dbMetaCount` 与 `dbCount`，不能用局部 `dbSqlMs` 从全部 `dbMs` 中相减后声称得到了网络时间。Region 为最后一个有效元数据的区域，缺失不推断。
- 没有新增索引或更改数据库结构。通过真实迁移后的 SQLite 检查共享读取与删除后讨论可见性；线上耗时仍以新日志为准。

## 其它流程查询优化

- 普通回复、保存帖子不再通过 `getPost` 读取未使用的标签和附件；写入仍保持原有批量事务和新鲜权限/版本检查。
- 帖子列表只投影卡片字段，规范化搜索文本取前 152 个字符供 150 字摘要判断省略号；空搜索文本的历史记录仍回退完整 Markdown，避免破坏旧内容的摘要。标签筛选并入子查询，标签及两类计数合为一次 D1 batch。分页总数先行的越界纠正语义保留。
- 普通回复的目标用户合并到窄字段联查。通知/动态的生命周期上下文合为一次 batch，并对讨论状态去重；仍按作者与删除/隐藏状态判断可达性。
- 资源访问一次返回引用聚合计数，保留临时、历史、隐藏、头像引用的权限规则；管理员总览的四类统计合为一次 batch。
- 这些是往返与数据量优化，实际延迟改善仍需用线上探针比较；没有新增缓存、索引或修改数据库结构。

## 第三轮：减少关键路径往返与访问分组

- 批注回复的去重、批注状态、帖子窄字段、当前锚点和回复目标读取合成一个只读 batch；写入守卫和幂等行为保留。稳定状态下鉴权的白名单与资料查询合为一次 JOIN，管理员配置异常时仍走原有修复。Action/API 不复用页面缓存，页面仅请求内共享。
- `probeVersion: 3` 标识这一轮。浏览器使用随机 `browserId`（localStorage）和 `sessionId`（sessionStorage），用于区分浏览器配置与标签页会话；清理存储、无痕或拒绝存储会改变标识，不能当作物理设备指纹。没有 Canvas、字体、音频指纹，也不关联登录身份。
- 服务端根据请求头提供受限的设备类型、浏览器主版本、操作系统，以及 IPv4 /24、IPv6 /48 的 `networkPrefix`；不保存完整 IP 或原始 User-Agent。网段可能是代理出口，多个设备可能相同。country/colo 仅平台提供时记录，不推断真实位置。客户端记录中的这些字段代表上报请求环境，不保证与原请求的网络状态完全相同。
- 增加连接有效类型、估算 RTT/下行带宽（浏览器支持时）、前台/后台、在线状态、HTTP 协议、资源类型及传输前后字节数。`preRequestMs` 是 startTime 至 requestStart，包含排队、重定向、建连等，不能叫纯排队时间。导航 duration 改为 responseEnd-startTime，避免 load 完成前得到零；DOM 时刻仍单独记录。
- 服务端记录预取标记；fetch 失败区分 AbortError、TypeError 和其它错误（TypeError 也不必然是网络故障）。交互保留受限事件类型。性能上下文关联已记录错误的 incidentId，避免 HTTP 200 的失败 Action 混入成功样本。
- 分组数据只用于管理员诊断，不参与鉴权。仍为 5,000 条滚动上限；客户端同时限制每批 30 条及约 23KB，上报失败不重试。
